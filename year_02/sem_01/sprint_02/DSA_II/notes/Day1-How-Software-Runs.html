How Software Runs

What software is, how data turns into information, where data structures fit next to files and databases, and what the computer does between your double-click and the moment a program starts running.

Terms with a dotted underline have a short explanation: hover over them with a mouse, or tap them on a phone or projector screen. Press Esc to close.

01Hardware, software, and the layers between

Hardware is the physical machine: the Central Processing Unit (CPU), Random Access Memory (RAM), the Solid State Drive (SSD) or hard disk, keyboard, screen. On its own it can only follow very simple instructions, one after another.

Software is a set of instructions plus the data those instructions work on. A program is software saved as a file. A program that is currently running is called a process. The same program can run as several processes at once: run your own compiled program twice, and the OS creates two separate processes from one file.

Software is organised in layers. Each layer uses the one below it and hides its details from the one above.

You (the user)clicks, types, reads the screen
Application softwareChrome, Microsoft Word, Visual Studio Code, WhatsApp, games
System softwareOperating System (OS): Windows, Linux, Android · device drivers
HardwareCPU, RAM, SSD, screen, Wi-Fi card

A program's whole purpose is this conversion: take data in, process it, produce information. How fast it can do that depends heavily on how the data is organised, which is where data structures come in.

04What a data structure is

A data structure is a way of arranging data in memory so that the things a program needs to do with it (find, add, remove, get the smallest, and so on) are fast. Think of a library: books thrown in a pile and books arranged on shelves by subject hold the same books, but finding one takes very different effort.

Suppose 1,000,000 student roll numbers are stored and one must be found:

How the roll numbers are arrangedHow to find oneWorst-case checks
Array in random orderCheck one by one from the start (linear search)1,000,000
Sorted arrayLook at the middle, throw away the wrong half, repeat (binary search)20

Why 20? Each check halves what is left. Halving 1,000,000 twenty times gets below 1, because 220 = 1,048,576 is more than 1,000,000. Same data, same computer: 50,000 times fewer checks, just from arranging it well.

Data structures come in two shapes. Linear ones keep elements in a line: array, linked list, stack, queue. Non-linear ones branch out: tree, heap, graph. This course goes through them module by module: arrays (Module I), linked lists (Module II), trees and heaps (Module III), hashing and graphs (Module IV), and graph algorithms (Module V).

05Data structure vs file vs Database Management System

These three all hold data, but they do different jobs: a data structure organises data inside a running program, a file keeps data on the disk, and a Database Management System (DBMS) is software that looks after large amounts of shared data for many users.

Why databases exist when files already do

Imagine a college keeping student records in plain files. The same student's phone number gets copied into the fees file, the library file and the exam file. One copy gets updated and the others don't, so now nobody knows which is right. Two clerks save the same file at the same time and one person's changes vanish. The power goes off halfway through saving and the file is left half-written. A DBMS is built to prevent exactly these problems, in one place, for everyone.

How the three connect

They work together. A DBMS stores its tables in files on disk, and uses data structures (the kind this course teaches) to find rows quickly. When your program reads rows from a database or a file, it puts them into its own data structures in RAM to work with them.

memory_regions.c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>

int initializedGlobal = 42;     /* data segment   (global with a starting value) */
int uninitializedGlobal;        /* BSS segment    (global with no starting value, set to 0) */

void sayHello(void) {           /* code (text) segment: the machine instructions */
    printf("Hello from the code segment\n");
}

int main(void) {
    static int counter = 7;     /* data segment   (static local lives for the whole run) */
    int localVar = 10;          /* stack          (exists only while main() runs) */
    int *heapVar = malloc(sizeof(int));  /* heap  (exists until free) */
    *heapVar = 20;

    sayHello();
    printf("code  : sayHello            at %p\n", (void *)(uintptr_t)&sayHello);
    printf("data  : initializedGlobal   at %p\n", (void *)&initializedGlobal);
    printf("data  : counter (static)    at %p\n", (void *)&counter);
    printf("bss   : uninitializedGlobal at %p  value = %d\n", (void *)&uninitializedGlobal, uninitializedGlobal);
    printf("heap  : *heapVar            at %p\n", (void *)heapVar);
    printf("stack : localVar            at %p\n", (void *)&localVar);

    free(heapVar);              /* give heap memory back */
    return 0;
}

MemoryDemo.java
// Java does not let a program see real memory addresses,
// so this program shows WHERE each value lives using comments and output.
public class MemoryDemo {
    static int initializedStatic = 42;   // method area: class data, lives for the whole run
    static int uninitializedStatic;      // method area: Java gives it the default value 0

    static void sayHello() {             // method area: the method's bytecode
        System.out.println("Hello from a method stored in the method area");
    }

    public static void main(String[] args) {
        int localVar = 10;               // stack: inside main's frame
        int[] heapArray = new int[3];    // the array object -> heap; the reference heapArray -> stack
        heapArray[0] = 20;

        sayHello();
        System.out.println("method area : initializedStatic   = " + initializedStatic);
        System.out.println("method area : uninitializedStatic = " + uninitializedStatic + " (default value 0)");
        System.out.println("heap        : heapArray[0]        = " + heapArray[0] + " (every object lives on the heap)");
        System.out.println("stack       : localVar            = " + localVar + " (gone when main returns)");

        heapArray = null;                // no delete in Java: the garbage collector frees it later
    }
}

09Common mix-ups

Common belief: on double-click the whole program is copied into RAM before it starts.

Actually: the OS brings in only the parts the program needs right now, and loads the rest later if and when it is used. Parts that never run may never enter RAM. That is why even a big app can open in a second or two.

Common belief: the application sets up its own environment.

Actually: the operating system sets it up: the Process ID, the private memory, the stack and the heap. The application's own code starts only at the very end, when main() is called (or, in Python and JavaScript, when the first line of your file runs).

Common belief: data structures, files and databases are three alternatives to choose from.

Actually: they work together. Data structures hold data in RAM while a program runs, files keep data on disk, and a DBMS looks after shared data stored in files.

Common belief: RAM holds everything and the disk is just for backup.

Actually: RAM is cleared when the power goes off. Anything that must be kept, such as the program file itself, documents and databases, has to be on disk. RAM is the fast work desk; the disk is the cupboard.

10How fast is a program? Time and space complexity

Two programs can solve the same problem, yet one finishes instantly and the other takes hours. To compare them fairly we don't use seconds, because seconds depend on the computer. We count steps and ask: how does the number of steps grow when the input gets bigger?

Time complexity describes how the number of steps grows with the input size n. Space complexity describes how much extra memory the program needs as n grows. Both are written in Big-O notation, read as "order of": O(n) is "order n".

O(1)
Constant

Same steps whatever the size.
O(log n)
Logarithmic

Halves the work each step.
O(n)
Linear

One pass over the input.
O(n²)
Quadratic

Every item meets every item.
O(2ⁿ)
Exponential

Doubles with each extra item.

/* O(1): look at the first element. One step, however long the list is. */
void printFirst(const int a[], int n) {

    steps++;

#include <stdio.h>

/* O(n): one simple loop visits every element once. */
void printAll(const int a[], int n) {
    int steps = 0;
    printf("n = %d:", n);
    for (int i = 0; i < n; i++) {
        printf(" %d", a[i]);
        steps++;
    }
    printf(" -> steps = %d\n", steps);
}

int main(void) {
    int small[] = {7, 3, 9, 4, 1};
    int big[] = {7, 3, 9, 4, 1, 8, 2, 6, 5, 0};
    printAll(small, 5);
    printAll(big, 10);
    return 0;
}

Logarithmic time: binary search

    

      
Think of it like this
Finding a word in a dictionary: open the middle, see if your word comes before or after, and throw away the other half. Repeat. Even a huge dictionary needs only a few looks.

      
What the code does
The list must be sorted. Look at the middle element. If it is too small, the answer can only be on the right; if too big, only on the left. Each step halves what is left, so doubling n adds just one step.

/* O(log n): binary search. Each step throws away half of what is left. */
void binarySearch(const int a[], int n, int target) {
    int lo = 0, hi = n - 1;
    int steps = 0;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        steps++;
        printf("lo=%d hi=%d mid=%d a[mid]=%d", lo, hi, mid, a[mid]);
        if (a[mid] == target) {
            printf(" -> found\n");
            printf("n = %d: found %d, steps = %d\n", n, target, steps);
            return;
        } else if (a[mid] < target) {
            printf(" < %d -> search right half\n", target);
            lo = mid + 1;
        } else {
            printf(" > %d -> search left half\n", target);
            hi = mid - 1;
        }
    }
    printf("n = %d: %d not found, steps = %d\n", n, target, steps);
}

O(2ⁿ)
Exponential time: recursive Fibonacci

    

      
Think of it like this
A rumour where every person tells two new people. After a few rounds the number of people explodes: 2, 4, 8, 16, 32…

      
What the code does
Fibonacci numbers: 0, 1, 1, 2, 3, 5, 8… each is the sum of the two before. fib(n) calls fib(n − 1) and fib(n − 2), and each of those calls two more. The same values get worked out again and again (marked as repeats in the tree). The calls grow roughly doubling with n, so O(2ⁿ) is the usual upper bound.

      
Pseudocode


fib(n):
    if n < 2: return n
    return fib(n − 1) + fib(n − 2)

#include <stdio.h>

/* O(2^n): recursive Fibonacci. Each call makes two more calls. */
long long calls = 0;

long long fib(int n, int depth, int show) {
    calls++;
    if (show) printf("%*sfib(%d)\n", 2 * depth, "", n);
    if (n < 2) return n;                                   /* fib(0) = 0, fib(1) = 1 */
    return fib(n - 1, depth + 1, show) + fib(n - 2, depth + 1, show);
}

int main(void) {
    calls = 0;
    long long r = fib(5, 0, 1);                            /* print every call for n = 5 */
    printf("fib(5) = %lld, calls = %lld\n", r, calls);
    int sizes[] = {10, 20, 25};
    for (int k = 0; k < 3; k++) {
        calls = 0;
        r = fib(sizes[k], 0, 0);                           /* just count the calls */
        printf("fib(%d) = %lld, calls = %lld\n", sizes[k], r, calls);
    }
    return 0;
}

// O(2^n): recursive Fibonacci. Each call makes two more calls.

    calls++;
    if (show) cout << string(2 * depth, ' ') << "fib(" << n << ")\n";
    if (n < 2) return n;                                   // fib(0) = 0, fib(1) = 1
    return fib(n - 1, depth + 1, show) + fib(n - 2, depth + 1, show);
}

    for (int n : sizes) {
        calls = 0;
        r = fib(n, 0, false);                              // just count the calls
        cout << "fib(" << n << ") = " << r << ", calls = " << calls << "\n";
    }
    return 0;
}

// O(2^n): recursive Fibonacci. Each call makes two more calls.
public class ExponentialTime {
    static long calls = 0;

    static long fib(int n, int depth, boolean show) {
        calls++;
        if (show) System.out.println("  ".repeat(depth) + "fib(" + n + ")");
        if (n < 2) return n;                                   // fib(0) = 0, fib(1) = 1
        return fib(n - 1, depth + 1, show) + fib(n - 2, depth + 1, show);
    }

    public static void main(String[] args) {
        calls = 0;
        long r = fib(5, 0, true);                              // print every call for n = 5
        System.out.println("fib(5) = " + r + ", calls = " + calls);
        int[] sizes = {10, 20, 25};
        for (int n : sizes) {
            calls = 0;
            r = fib(n, 0, false);                              // just count the calls
            System.out.println("fib(" + n + ") = " + r + ", calls = " + calls);
        }
    }
}

Three rules for writing Big-O

    
    
      
  1. Look at the worst case. Assume the answer is found as late as possible (like binary search when the target is missing).
    2. 
      
  2. Drop constant factors. n ÷ 2 steps and 3n steps are both O(n): they grow the same way.
    3. 
      
  3. Keep only the biggest term. n² + n is O(n²), because for large n the n² part is almost everything.
    4. 
    

  

  

    
Space complexity in these examples

    
The first four keep only a few number variables (i, j, lo, hi, mid, steps), whatever n is: O(1) extra space. The input list itself is not counted as extra. Recursive Fibonacci is different: each call waits for the calls below it, and the deepest chain is n calls long, so it needs O(n) extra space on the stack.

  







  
11Quick check

  
1. A device driver for a printer: system or application software? Why?
Show answer
System software. It controls the printer hardware directly so that other programs can print without knowing how that printer works.

  
2. "Attendance this week: 38 out of 45 students, 84.4%." Data or information?
Show answer
Information. It is processed (counted and turned into a percentage) and has context. The individual present/absent marks it came from are the data. 38 ÷ 45 = 0.8444…, so 84.4%.

  
3. You open the same .exe twice. How many programs and how many processes are there?
Show answer
One program (one file on disk) and two processes. Each has its own Process ID and its own private memory, so their variables are completely separate.

  
4. In which memory region does each live: a global int total;, a local int i in a loop, and new int[100]malloc(100 * sizeof(int))?
Show answer
int total; outside any function is in BSS (set to 0). The local i is on the stack. The 100 integers are on the heap, and the pointer that holds their address is on the stack if it is a local variable.

  
4. In which memory region does each live: static int total;, a local int i in a loop, and new int[100]?
Show answer
static int total; is in the method area (default value 0). The local i is on the stack. The array is on the heap, and the reference that points to it is on the stack if it is a local variable.

  
4. Inside a function, scores = [70, 80]const scores = [70, 80];. Where does the name scores live, and where does the list of numbers live?
Show answer
The name scores is in the function's frame on the stack and disappears when the function returns. The list itself is an object on the heap, freed automatically once nothing refers to it.

  
5. A program stores 10 lakh orders in an array in memory. The power goes off. What happens to the orders, and what should have been used?
Show answer
They are lost, because the array lives in RAM, which is cleared when power goes off. They should have been saved on disk, ideally in a DBMS, since many users may place orders at once.

  
6. A program has a loop over n items, and inside it another loop over n items. What is its time complexity?
Show answer
O(n²). The inside loop runs n times for each of the n outer steps: n × n steps.

  
7. A loop starts with n and halves it each time until it reaches 1. Roughly how many times does it run for n = 1,024?
Show answer
10 times, because 210 = 1,024. Halving gives O(log n).

  
8. Binary search only keeps lo, hi and mid, whatever the size of the list. What is its space complexity?
Show answer
O(1), constant extra space. The number of extra variables does not grow with n.






  
12Glossary

  

    
CPU
Central Processing Unit: the chip that follows the program's instructions

    
RAM
Random Access Memory: fast working memory, cleared when power goes off

    
SSD
Solid State Drive: storage that keeps files when power is off

    
OS
Operating System: system software that manages the computer and runs other programs

    
BIOS / UEFI
Basic Input/Output System / Unified Extensible Firmware Interface: built-in software that starts the computer and then starts the OS

    
DBMS
Database Management System: software that stores and protects shared data

    
SQL
Structured Query Language: the language used to ask a database for data

    
CSV
Comma-Separated Values: a plain-text file that stores a table

    
PID
Process ID: the number the OS gives each running program

    
O( )
Big-O notation, read "order of": how the steps or memory of a program grow as the input size n grows

    
BSS
Block Started by Symbol: the memory region for global variables with no starting value (or a starting value of 0)

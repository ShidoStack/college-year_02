Inclusive vs Exclusive Max Arrays

The same input traced with two dynamic programming versions and the two-pointer optimisation. Both give the correct answer of 6 units. They differ only in whether bar i counts itself when finding the tallest bar on each side, and that decides whether the formula needs a clamp.

Theme:

Inclusive (counts bar i)

leftMax[i]
tallest bar in indices 0 … i
rightMax[i]
tallest bar in indices i … n−1
base case
leftMax[0] = height[0], rightMax[n−1] = height[n−1]
water[i] = min(leftMax[i], rightMax[i]) − height[i]

Both maxima are at least height[i], so the result is never negative. No clamp needed.

Exclusive (leaves bar i out)

leftMax[i]
tallest bar in indices 0 … i−1
rightMax[i]
tallest bar in indices i+1 … n−1
base case
leftMax[0] = 0, rightMax[n−1] = 0 (nothing there, ground level)
water[i] = max(0, min(leftMax[i], rightMax[i]) − height[i])

A bar taller than everything on one side gives a negative value. The max(0, …) clamp turns it into 0.

Version 3 · Optimised

Two pointers: the DP formula without the arrays

1 · What DP does

Builds both arrays first, so for every bar it knows leftMax[i] and rightMax[i] exactly. Then water[i] = min(leftMax[i], rightMax[i]) − height[i]. Cost: two extra arrays, O(n) space.

2 · What two pointers notices

The formula only ever uses the smaller of the two maxima. If we can prove which side is smaller, we only need that side's max, and it can be kept in one variable per side.

3 · The check that proves it

if (height[left] < height[right])

The bar at R is taller, so the true rightMax is at least height[right], which is at least leftMax. So min = leftMax, known exactly. Otherwise the mirror case: min = rightMax.

Full dry run

Why the check matters: it always picks the DP minimum

Each bar's DP values side by side with the side the two pointers chose. In every row the chosen side is the one with the smaller DP max.

What goes wrong without the check

Suppose we ignore the check and always use leftMax. At index 8 (height 2): leftMax = 3, so we would add 3 − 2 = 1. DP says min(3, 2) − 2 = 0, because the right wall (2) is the real limit. Doing that for every bar gives a total of 11 instead of 6. The check stops us from using a max that is not the bottleneck.

Java

public int trap(int[] height) {
    int left = 0, right = height.length - 1;
    int leftMax = 0, rightMax = 0, water = 0;

    while (left < right) {
        if (height[left] < height[right]) {
            // left side is the bottleneck
            leftMax = Math.max(leftMax, height[left]);
            water += leftMax - height[left];
            left++;
        } else {
            // right side is the bottleneck
            rightMax = Math.max(rightMax, height[right]);
            water += rightMax - height[right];
            right--;
        }
    }
    return water;
}

C++

#include <bits/stdc++.h>
using namespace std;

int trap(vector<int>& height) {
    int left = 0, right = (int)height.size() - 1;
    int leftMax = 0, rightMax = 0, water = 0;

    while (left < right) {
        if (height[left] < height[right]) {
            // left side is the bottleneck
            leftMax = max(leftMax, height[left]);
            water += leftMax - height[left];
            left++;
        } else {
            // right side is the bottleneck
            rightMax = max(rightMax, height[right]);
            water += rightMax - height[right];
            right--;
        }
    }
    return water;
}

Rule to remember: if the arrays include the bar itself, use the plain formula. If they exclude it, wrap it in max(0, …). Never mix inclusive arrays from one version with the formula of the other.
